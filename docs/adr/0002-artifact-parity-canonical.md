# ADR-0002 아티팩트 1:1 패리티와 정본 원칙

- 상태: 제안
- 날짜: 2026-11-03

| 항목 | 내용 |
|---|---|
| 맥락 | 화면·디자인은 Claude 아티팩트 게시본(`app/index.html`)으로 이미 확정됐다. 플랫폼 이전 중 화면이 조금씩 달라지면 비교 기준이 사라지고 검수가 주관적이 된다. 사용자는 1:1 동일을 지시했다(D1). |
| 선택 | **정본 = 아티팩트 게시본 `app/index.html`** (그다음 `SITE_FACTS.md` → `PLAN.md` 순). To-Be는 화면 13개(S01–S13)·모달 6종(M1–M6)의 구조·디자인 토큰·문구·상호작용·폴백을 그대로 옮기고, **저장·인증·데이터 출처만** 바꾼다. 추가 화면은 T1 로그인·T2 가져오기(D11). 사이트 결함 수정(D7: 미사용 `st.routines`·`ART` 제거, 하드코딩 개수 → 실제 개수)은 화면 모양을 바꾸지 않는 범위에서 명시된 것만 허용. |
| 대안 | ① 이전하면서 UI 개선: 기준이 흔들리고 범위가 커진다 — 이후 단계로. ② 디자인을 Figma로 다시 정본화: 이미 동작하는 정본이 있어 중복. |
| 결과 | 얻음: 검수 기준이 명확(같은 뷰포트 스크린샷 비교 [추정: `shot` 도구 사용]), 기획 문서는 사실 시트를 인용만 하면 됨. 잃음: 해시 라우팅 등 구조상 불가피한 차이는 문서에 예외로 적어야 함(02 §1.2). 되돌리기: 원칙 변경은 이 ADR을 대체하는 새 ADR로 — 낮은 비용. |
