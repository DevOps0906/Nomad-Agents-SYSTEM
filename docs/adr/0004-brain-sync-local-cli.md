# ADR-0004 second-brain 연동은 로컬 CLI + 색인 업로드

- 상태: 제안
- 날짜: 2026-11-03

| 항목 | 내용 |
|---|---|
| 맥락 | 탐색기·홈 입자 구는 As-Is에서 예시 노드 25·링크 26 상수다. 사용자의 실제 second-brain(로컬 Markdown 폴더, Obsidian 류)을 보여 주려면 폴더 → 그래프를 어떻게 얻을지 정해야 한다(D6·D22). 노트 본문은 개인 정보라 서버에 두지 않는 것이 원칙이다. |
| 선택 | 로컬 CLI `nomad-brain sync`(Node)가 폴더를 읽어 front-matter·제목·`[[위키링크]]`·Markdown 링크로 `graph.json`을 만들고(`.brainignore` 제외), 개인 액세스 토큰(`brain:write`만, 해시 저장, 언제든 폐기)으로 Route Handler에 올린다. 보내는 것은 이름·경로·분야·요약(front-matter `summary:`가 있을 때만, 200자 — 본문 자동 추출 금지)뿐, **본문은 보내지 않는다**. `--dry-run`으로 보낼 목록을 먼저 보여 주고, 토큰은 OS 키체인(없으면 `~/.config/nomad-brain/token` 0600)에 둔다(D37). 대체 경로는 웹에서 **폴더 선택 → 브라우저에서 색인**(본문은 기기 밖으로 안 나감)이라 CLI 없이도 된다. 상한·Pro·레이트 리밋은 DB 함수가 기준(4MB, D35). Pro가 끝나면 내 그래프는 읽기 전용, 업로드만 막힌다(D37). MVP-2(D39). 정적 사이트 생성기·Obsidian 게시와 같은 "로컬 폴더 → 색인 → 업로드" 관례. 흐름은 02 flow-4, 엔드포인트는 `04_API.md` B절 참조. |
| 대안 | ① 데스크톱 익스텐션(Claude Desktop 등): 설치·권한 모델이 무겁고 플랫폼 종속, MVP 범위를 넘는다. ② 폴더 직접 업로드(본문 포함): 가장 쉽지만 본문이 서버에 저장되어 민감 데이터·보관 의무(D27)·용량이 커지고 L2 보안 수준을 넘는다. ③ GitHub 연동(저장소 읽기): OAuth 앱·저장소 읽기 권한이 과하고, 폴더를 Git에 두지 않는 사용자는 못 쓴다. |
| 결과 | 얻음: 본문이 기기 밖으로 나가지 않음(웹 대체 경로 포함), 서버는 검증·저장만(작은 노출 면), 토큰 범위가 좁아 유출 피해 제한. 잃음: CLI 설치·실행이라는 사용자 단계, CLI 배포·버전 관리, `graph.json` 스키마를 CLI와 서버가 함께 지켜야 함. 되돌리기: 업로드 형식이 `graph.json` 하나라 다른 수집기(익스텐션 등)로 바꿔도 서버는 그대로 — 낮은 비용. |
