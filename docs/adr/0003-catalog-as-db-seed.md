# ADR-0003 카탈로그를 DB 시드로 이전

- 상태: 제안
- 날짜: 2026-11-03

| 항목 | 내용 |
|---|---|
| 맥락 | 사이트의 읽기 전용 내용(SSR 단계·레벨·프롬프트 `window.__D`, ArtCraft 16종, 가이드 쪽 텍스트, 7일 계획 기본값, 체크리스트, 브랜드 팔레트, 콘텐츠 시드, 탐색기 노드 25·엣지)은 모두 파일 내 상수다(SITE_FACTS 4.4·5.2·8). 플랫폼에서 이 내용을 어디에 둘지 정해야 한다(D4). |
| 선택 | 카탈로그를 **Supabase 읽기 전용 테이블**로 두고, 사이트 상수를 그대로 추출한 **시드 SQL**로 채운다. RLS는 select 공개, insert/update/delete는 admin만. 화면은 서버에서 읽고 캐시한다(02 flow-2). 편집 UI 여부는 미결(Q3) — MVP는 시드·마이그레이션으로만 수정. |
| 대안 | ① 코드 상수(TS 파일): 가장 단순하고 타입 안전하나, 내용 수정마다 배포가 필요하고 이후 graph.json 업로드(D6·Q4)·ArtCraft 정보 갱신과 맞지 않는다. ② MDX/콘텐츠 파일: 가이드 같은 장문엔 맞지만 탐색기 노드·엣지·체크리스트 같은 구조 데이터엔 부적합하고 사용자 데이터와 조인(예: 최근 파일 → 노드 id)이 어렵다. |
| 결과 | 얻음: 사용자 데이터와 같은 저장소·참조 무결성(노드 id), 배포 없이 내용 갱신, 이후 관리자 화면 확장 여지. 잃음: 시드 추출·동기화 작업, 렌더마다 DB 조회(캐시로 완화), 타입은 생성(`supabase gen types`)으로 맞춰야 함. 되돌리기: 시드 SQL을 TS 상수로 바꾸는 변환은 기계적 — 낮음~중간 비용. |
